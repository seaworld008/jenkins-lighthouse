# 回滚

回滚方案要在切换前写好，并在演练环境里实际跑一遍。

## 前提：切换时保留这些

- 旧服务的 unit / Tomcat 配置、旧 war、旧运行 JDK，都不删除，只是停止并取消开机启动。
- 旧 JENKINS_HOME 原样改名保留（例如 `<HOME>.pre-upgrade-<日期>`），或保留停机后的最终快照。
- 被修改的系统文件都先备份：`/etc/profile`、`/etc/fstab`、alternatives 的当前选择、nginx 配置。
- 新控制器的数据目录与旧目录分开，回滚不需要"还原数据"。

## 三种粒度

| 粒度 | 场景 | 做法 | 经验耗时 |
|---|---|---|---|
| 整体回滚 | 新核心有无法短期解决的问题 | `assets/rollback.sh.tmpl`：停 agent、停控制器、恢复挂载和 `/etc/profile`、改回旧 HOME、启动旧服务 | 约 2 分钟 |
| 只回退运行 Java | 25 上有插件兼容问题 | 用 `-jdk21` 镜像标签和 Java 21 的 agent unit 覆盖，重启 | 约 1 分钟 |
| 只回退编译 JDK | 新 JDK 8 打出的包有差异 | 恢复 `/etc/profile` 备份、alternatives、全局 JDK 工具 | 几分钟 |

## 回滚的代价

- 切换后新产生的构建记录、配置修改不会回到旧环境。回滚窗口内尽量不改任务配置；需要的话事后手工补。
- webhook 地址如果已经改到新入口，回滚后要确认旧入口仍然可达。

## 什么时候可以释放旧数据

回滚窗口（建议一周）内没有回滚需求，且至少做过一次新环境的全量备份并核对内容后，再释放旧 HOME、旧快照。释放前向用户确认。
